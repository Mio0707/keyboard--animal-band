# 音乐编曲与互动配乐

制作有完整音乐结构、可复现的歌曲编曲与配乐；有互动玩法时再与玩法协调。先解决作曲、时序与声部配合，再调整单层音色。保持用户已认可的部分；用新版本输出试验结果。

用户要“换一首歌改编并演奏”时，先读[歌曲输入到演奏交付](references/song-input-performance.md)。使用随Skill提供的`scripts/song_bundle.py`完成输入校验、显式改编谱、渲染、检查和独立演奏页打包，不依赖《茉莉花》项目脚本或本机库存路径。已有MIDI／可核对谱面的固定速度歌曲可走此链；仅有音频时先解决转谱，不声称已支持任意MP3自动准确改编。

## 歌曲＋风格直接交付

用户只给歌名和目标风格时，按[歌曲输入到演奏交付](references/song-input-performance.md)执行完整流程：查可核对曲谱、整理源谱、按曲风编配、核实本地音色、渲染、检查、打包并启动演奏网页。默认继续做到网页，不停在编曲方案、音频或代码片段；不要求用户逐条运行内部命令。只在歌曲版本有实质歧义、无可靠谱面或缺少必要音源时提出具体缺口。

默认支持八键和旋钮映射，KEY6/7每次4小节；提供启动入口、试听与源谱。使用轻量通用演奏页；用户要求动物舞台时再做对应形态适配。通用页可支持新配器，不冒称已包含所有动物动作。技术检查通过与听感认可分开报告。

## 工作流程

### 1. 明确情绪、风格与用途

从用户与项目中提炼：主题、2–3 个情绪词、希望避免的听感、领奏/人声是谁，以及歌曲的使用场景。有互动玩法时再确定哪些事件改变节奏。信息足够就执行；只问会实质改变方向的缺失信息。

指定流派或做风格改编时，只读 [流派编曲](references/genre-arranging.md) 的对应路线；需要核对依据时查 [知识来源](references/authoritative-sources.md)。公开课程大纲仅作知识路线，不声称已读未公开的课程。

Phonk改编先读[Phonk专页](references/phonk.md)，确定经典或Drift路线，核对牛铃源样本与移调渲染能力。

Bossa Nova改编另读 [Bossa谱例与实施](references/bossa-nova.md)。其他流派若现有资料只有概括，先查一个直接谱例/教师示范，写出细分拍、声部配合、重音/音长与旋律改写实例，再生成音符；不要用更多流派形容词代替制作决策。

把情绪翻译成音乐选择：旋律走向、和声张力、音符密度、触音、音区、音色和空间感共同决定听感。“明亮”不等于一律提高音调或增加高频；“氛围”不要求持续长音。

### 2. 核对并确定共同拍点

有工程时先读实际节奏数据、运行时事件修改和调度代码，再作曲。核对 BPM、字点/操作落点、句长、句间空隙、变速、暂停和恢复。

- 音乐、语音和判定使用同一个拍到时间的映射。仅 BPM 一样不能保证对齐，还要验证起点与拍相位。
- 基础拍与内容节奏分开。长字可以跨拍，短字可以在细分拍上；均匀底拍不应自动变成逐字重音。
- 句间呼吸可写进音乐句长。任意小数间隔叠加可能让后续句子偏离底拍；区分有意的切分/自由节奏与无意偏移，不机械地量化所有项目。
- 尊重用户对底拍强弱、字点重音的选择。不要因本技能默认采用固定拍号、速度或句长。
- 若需要改变既有玩法时序，在试听提案中明确记录变化；仅要求配乐不意味着直接改动正式关卡或判定。已授权修改玩法时按对应范围执行。

### 3. 按声音职责选择能配合的乐器

进行流派改编时，读取[专业编曲与配器路线](references/style-production.md)的目标段落，以及[音色库选择与渲染](references/sound-selection.md)。先生成实际音色选择清单，核对库存和奏法限制，再写谱/渲染；不能凭GM编号猜乐器、用通用铃鼓冒充Pandeiro，或把网页采样子集当成全部SoundFont库存。

先列职责，再选配器：主旋律、和声/伴奏、低音、拍感、反馈；可由少量乐器兼任，无需固定五层。

说明每件乐器如何服务情绪，以及与其他声部、人声的关系。综合音色材质、起音、衰减、音区、演奏密度与力度；相似音色有助融合，对比音色也可有意使用。

选择能保留合适演奏细节的音源。自然、轻巧的题材可优先试采样乐器；电子题材可以用合成器。不要以简单波形加泛音替代全部配器判断，也不要把某个成功案例的乐器组合套到所有主题。

### 4. 先写完整乐句，再统一编配

涉及Build/Drop、间奏或高潮时，读[分流派段落推进](references/section-energy.md)：先定音乐功能与乐句发展，再决定名称和手法；不要只给主题加力度，也不要在渲染器里统一截掉所有Build末拍。

八键现场演奏的按次队列默认用4小节独立短句；完整主题保留原曲长度。过渡与变奏改变声部职责、律动或动机，不能只复制主题加力度。用户明确选择其他触发长度时，以其选择为准。

先确定调性/音阶、和弦与低音走向、可辨认的主题及回应、重复和变奏、段落过渡与收尾。适合时先做短乐段验证方向，再扩展到所需长度；这不要求每步停下来请用户确认。

新流派、重大重编或出现多轨冲突时，先按 [合奏验证与排错](references/ensemble-review.md) 做一个完整乐句的小样，再扩展完整编曲。鼓贝、旋律与和声、全部声部应在同一混音平衡下分别验证；不能只试听独奏声部。此流程不要求每一步向用户确认。

旋律、和弦、低音共同检查，明确经过音和张力音的去向。避免把“从同一音阶抽取音符”当成完整作曲。音乐可以跨越多个内容句，不能每个字都重新触发一个互不关联的音。

不要把临时修订当流派通则：鼓贝不必每音重合，半音/非和弦音不自动判错，统一延长音符不能替代分句和呼吸。新曲风也不等于只换音色。

所有可同时播放的分轨从统一谱面或编曲导出，共享速度图、起点与结构。可按状态增减声部或切换段落；先设计衔接位置，避免为了响应事件随意打断乐句。需要立即回应的操作音不要为量化而增加延迟。

需要将多种风格接入同一演奏产品时，读[流派到演奏资产](references/style-to-performance.md)，将实施卡和实际音色选择保存在渲染清单，沿用代码检查；不增加重复提示词或把技术通过当作听感通过。

### 5. 渲染、加入语音和反馈、混音

制作时读取 [制作与验证约定](references/production.md)。根据可用环境选择可控的 MIDI/采样器、DAW 或其他合适工具；记录音源与渲染方式，不宣称未实际使用的音色来源。

先导出纯音乐，再加入语音和反馈。按玩法优先级安排音量，必要时对整句或适当时间尺度平滑压低伴奏，避免机械的逐字音量抽动。空间效果按风格需要添加，不能用回声和长音掩盖音乐结构缺失。

### 6. 验证并交付可试听版本

清单采用 `segments + sectionScores` 时，可运行 `python3 scripts/check_arrangement.py /绝对路径/manifest.json --output /绝对路径/检查结果.json`；格式和指标边界见 [合奏验证与排错](references/ensemble-review.md)。脚本区分错误、未检查项和描述性指标，不生成“好听分数”。其他工程沿用实际工具验证，不强行转成此格式。

验证真实音频的拍点、变速段、边界、语音完整度、音量与削波，以及分轨叠加结果。若任务包含实时接入，再检查实际游戏中的暂停恢复、剧情插入和判定同步。

交付完整试听、简短的设计规则和实际验证结果；纯音乐、分轨及可编辑谱面按任务需要提供。区分“技术检查通过”“已实际听过”和“用户认可”；自动检测不能证明好听。
