# 制作与验证约定

## 开始前的简短设计记录

记录以下内容即可，不需要写长篇企划：

- 主题、情绪、避免的听感；玩家需要听清的信号。
- 来源节奏数据与此次时序提案的区别；BPM/拍号变化及触发点。
- 乐器、职责、选择理由；主旋律与伴奏如何互相留空间。
- 乐句、和弦、变奏与收尾；用户已认可的基准。

新主题例子仅作起点：森林嬉戏可试短笛/拨弦/木质打击，太空机械可试清晰的合成器短音/电子低音/干净脉冲。仍需结合语音、操作密度和用户偏好判断，不能仅按主题标签选音色。

## 可复现的音乐结构

按项目需要保存等价信息，不强制特定格式：

- 速度图和段落：BPM、生效拍点、段落长度、和弦、循环/过渡位置。
- 音符：声部、音高、起点、时值、力度。MIDI note-off 不一定等于实际尾音结束。
- 内容事件：语音/操作 ID、拍点、目标时间、反馈规则。
- 渲染：采样率、音源/乐器名称、版本或来源、轨道增益与处理。

生成器使用显式谱面或可复现的受约束变化；如果使用随机性，记录种子及约束。参数改变后重新计算时间，不让独立循环或逐句重启产生累计相位偏移。

## 渲染选择

- MIDI＋采样器适合需要精确控制、变速和独立分轨的配乐。可用 FluidSynth＋SoundFont，或 macOS AVAudioUnitSampler 的离线渲染；先检查实际依赖。
- 外部生成或现成音频也可用，但需要验证真实拍点、速度、边界与分轨能力。不能把标称 BPM 当成已精确对齐。
- 自然音色的短促、干净触音与衰减往往比持续叠加泛音更适合密集语音；这不是禁止长音或合成器。
- 脚本以参数或配置接收音库路径，不把开发者私有路径作为必需依赖；不要默认远端音源、插件或付费服务可用。
- 输出独立草稿版本。若用户已授权替换或接入，完成相应操作；不要自行增加每一步的审批流程。

## 混音

以实际人声和操作信号为参照控制伴奏，不使用固定百分比代表所有音源。峰值、平均能量与主观响度不同。轻微、平滑地降低伴奏可以保留语音清晰度；根据句间连贯性选择压低范围。

反馈的音色、音区、时值和音量应能在混音里辨认。示例全中与真实玩家事件必须明确区分。实时反馈跟随输入/判定触发，不能用预录全中音轨替代交互逻辑。

## 验证与交付

- **时序**：同速段基础拍等间距；字点/操作点符合设计细分；变速和片段边界的相位明确。实际渲染起音也要抽查，不能只验证事件 JSON。
- **连贯**：检查引子、句间、长休止、变速、循环与收尾。底拍持续不等于声音无缝铺满；检查是否存在非预期的空白或断尾。
- **人声**：确认对齐与相邻字重叠情况。处理文件留白时保留辅音和自然尾音；不能用删掉字音来掩盖节奏冲突。
- **音频**：采样率/声道一致，数值有效，无削波；分轨保留共同长度、零点和混音增益，不各自归一化后声称能直接还原混音。
- **听感**：有实际听辨能力时检查尖锐、嗡鸣、拥挤、抢拍及循环疲劳。没有听辨证据时，准确报告为渲染/技术验证，不声称已听过或已验证舒适性。
- **接入**：仅在任务涉及游戏集成时测试暂停恢复、计时钟、事件暂停与输入延迟；离线试听不能证明这些已工作。

多轨拥挤、节奏不合或更换流派时，结合 [合奏验证与排错](ensemble-review.md) 检查；自动数据与用户听感冲突时，重新定位音乐问题，不用测试通过反驳用户反馈。

默认先交用户所需的试听，不强制增加产物。需要分轨时附纯 BGM、完整混音、各声部和简短参数记录；需要后续编辑时保留 MIDI/谱面。用简短文字说明改动、模拟部分和接入状态。
