# 《千字文·晴窗书声》：用户认可的 V6 案例

## 目标与反馈

目标：明亮、轻松、俏皮，逐字朗读清楚，底拍均匀，音乐跨句连贯。

用户不喜欢前几版的低沉铺底、突兀电子反馈、泛音叠加带来的“底噪感”、零碎的短音；明确要求底拍均匀，不按字点额外重击。重写音乐结构并换为采样乐器后的 V6，用户明确表示音乐满意，并特别认可配器。

这些偏好属于此案例，不能推断所有用户或所有主题都需要相同风格。

## 配器如何决定

| 声部 | 选择 | 设计理由 |
|---|---|---|
| 主旋律 | 马林巴 | 圆润、木质、起音清楚，适合轻快短乐句 |
| 和声伴奏 | 尼龙弦吉他 | 温暖拨弦，用分解和弦连接乐句，与木质触音协调 |
| 低音 | 原声贝斯 | 低音量托住和声，短时值避免持续低沉铺底 |
| 底拍 | 木块 | 同音高、同力度的短音，每拍一次，不加字点重音 |
| 命中反馈 | 较高音的木块 | 与底拍材质一致，用音高区分，短促、克制 |

“氛围”由整体编配形成，不另加持续长音轨。声部音色彼此协调，职责分明。没有规定所有音色必须相似，也没有把“国风”机械地等同于古琴或古筝。

## 作曲与拍点

- C 大调；C、F、G 和弦。写四句主题，再写回应和变奏；旋律与和弦一起设计，而非逐字随机挑选音阶音。
- 前 16 句和弦：`C F C G | C F G C | F G C F | C G C C`。
- 引子 4 拍，收尾 4 拍；主旋律收尾为 E–D–C。
- BPM 随段落为 72 → 88 → 104 → 88。
- 普通句：4 拍，字点 `[0,1,2,3]`。
- 犯困句：6 拍，字点 `[0,2,3,4]`；长的是第一字到第二字的间隔，不拉长原语音元音。
- 快句：4 拍，字点 `[0,0.75,1.5,2.25]`；最后留白由伴奏承接。
- `gapBeats=0`，呼吸放进句长。拍点草案使用引擎已有的事件修改和调度函数生成，与正式关卡分开。
- 80 个均匀底拍；每拍同音高、同力度，无额外字点打击。

## 音源、混音与验证

- 使用 macOS 内置 DLS 乐器音库，经 AVAudioUnitSampler 离线渲染；没有新增混响、回声或持续合成铺底。
- 五个交付分轨：伴奏（吉他＋贝斯）、旋律、底拍、朗读、反馈。
- 朗读期间旋律和伴奏的振幅平滑降至 0.73（约 −2.7 dB），平滑窗口 120 ms；没有逐字强烈压音。这是此音源下的参数，不是普适响度标准。
- 语音采用既有逐字录音，只裁除文件首尾留白，不改变音高或压缩时长。
- 56.709 秒，44.1 kHz/16-bit/双声道，64 个汉字；反馈模拟全中。
- 技术检查：无削波、末尾归静、分轨重建误差不超过 2 个 16-bit 量化单位；实测底拍起音偏差小于 1 ms，相邻语音最大重叠约 2.14 ms。
- 用户认可的是离线试听，尚不能据此宣称正式游戏已接入。原游戏的 1300 ms 剧情暂停未加入试听，未来接入需处理音乐时钟和过渡。

## 从本例迁移时保留什么

保留“情绪与玩法 → 共同拍点 → 声音职责与配器 → 完整作曲 → 统一编配 → 渲染混音 → 验证试听”的流程；新主题重新决定音阶、和声、乐器、空间感与节奏。C 大调、五层、木块、0.73 压低比例都不是硬性规则。

若原项目可访问，精确复现文件在其 `audio/drafts/v6/`：`prepare.mjs`、`compose.py`、`render-instruments.swift`、`mix.py`、`verify.py`、`score.json`。本技能不依赖原项目路径或这些文件才能用于新游戏。
