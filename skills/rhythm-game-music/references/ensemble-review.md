# 合奏验证与故障排查

适用于新曲风、重编曲，以及“节奏配不上、打架、断续、盖住旋律”等反馈。实践流程综合S1/S3/S4/S5/S7/S13/S14/S15/S16，见 [知识来源](authoritative-sources.md)；不是权威教材逐项规定。

## 先分清故障

- **运输/相位**：多个页面是否同时播放？分轨零点、速度图、原生帧数、小节长度是否一致？是否重复调度、错误变速或分段重启？
- **节奏组织**：能否听出共同脉搏和句首？哪些共同重音，哪些互补？只对齐BPM不等于合奏成立。
- **和声/音域**：领奏长音下的和弦是什么？低音如何连接？相邻半音可能是有意张力，不能机械删除。
- **织体/混音**：谁在说主句？持续音和起音是否遮蔽领奏？先做删减、换音域、改时值，再考虑EQ/动态。

## 风格对照

出现“风格不明显”时，先核对实际声部是否执行了目标演奏语法。已有版本则比较同一句、相近试听响度的A/B，单独提供节奏组/伴奏试听；不能仅增加扩展和弦或音色标签。无听辨能力时保留待试听状态，不声称模型已完成风格验证。

## 一次小样，四种组合

新风格或重大重编先做一个完整乐句，通常4–8小节；遇到长句按实际句长取样，不硬截为8小节。用同一个音源、速度图、起点和混音增益导出：

1. 鼓＋贝斯：共同脉搏稳定，互补有意图，低频不起糊。
2. 旋律＋和声：旋律识别句、换气、张力和解决成立。
3. 旋律＋鼓＋贝斯：旋律自然进入律动，不靠琴轨掩饰脱节。
4. 全部声部：加入伴奏后是否更清楚、有推进，而非更拥挤。

这是工作顺序，不是每步都要求用户审批。能实际听辨就自行迭代；不能听辨时提供一个短的完整合奏试听和简短差异，明确“待试听”，不要继续用自动分数宣称好听。用户已有的授权足够时继续制作，不强制插入确认关卡。

## 反馈到修改的最短路径

| 反馈 | 优先检查 | 先改什么 | 避免 |
|---|---|---|---|
| 一卡一卡 | 是否真正掉音；音符是否过短；重复起音是否过密 | 逐句改连断、删机械重击、修循环边界 | 无差别延长每个音，把原有休止和呼吸全部填满 |
| 节奏配不上 | 句首、小节相位、细分感觉、抢拍是否有意 | 选共同重音与互补关系，先只验证鼓贝＋旋律 | 所有轨一起量化/随机微移，或者只改音量 |
| 多轨打架 | 同音区、长尾、独立切分与装饰的叠加 | 暂停一个伴奏或装饰，减少重叠，再重配音域与时值 | 每条声部单独好听就认为叠加会好听 |
| 旋律不清楚 | 在全混音中比较音域、瞬态和遮蔽 | 留空、换配置/音色、重新平衡，必要时适度EQ/动态 | 用整段RMS指定每条轨固定百分比或把主旋律无限加大 |
| 不像目标流派 | 参考的整支节奏组、重音、演奏语法 | 校正主律动与角色，再补音色与装饰 | 只换萨克斯/鼓包/滤镜就称已完成风格转换 |

一次修一个层面，保留前版；同一段落、相近试听音量A/B，防止“更响”被误认为“更好”。

## 自动检查的边界

使用 `scripts/check_arrangement.py` 读取当前项目这类 `segments + sectionScores` 清单。脚本没有音乐评分器：

- **错误**：无效/越界音符时间、非法MIDI数值、WAV缺失/校验不匹配、分轨帧数或格式不一致、削波样本。
- **技术观察**：分轨叠加残差。总线压缩、饱和或混响路由可导致不能直接还原，应回查导出设计；不是机械判编曲错误。
- **待听辨数据**：实际重音重合比例、起音数量、音域、音符时值/空隙、相邻半音重叠、整段RMS。没有通用合格阈值；脚本不强迫鼓贝全重合、不禁止半音、不要求旋律占用时间越高越好。
- 不支持的格式/没有实际WAV标为未检查，不能伪装成技术通过。指标不能证明目标风格、张力解决、演奏自然或悦耳。

脚本约定：`bpm`、`beatsPerBar`、`segments[段落].duration/beats/assets`，以及`sectionScores[段落].tracks[轨道]`中的`midi/beat/duration/velocity/channel`。可选`trackRoles`用`lead/chords/bass/drums`映射；未提供时只对本项目dog/bear/cat/lion使用已有约定，不推断任意名字。PCM16 WAV使用标准库检查；其他格式需实际解码验证。

```sh
python3 scripts/check_arrangement.py /绝对路径/manifest.json --output /绝对路径/检查结果.json
```

## 本次茉莉花案例应留下的经验

初稿主旋律和伴奏分别编写切分；后续仅增加连音，没有重新审查合奏，用户仍听到冲突。随后采用简单共同重音和减少伴奏作为修订尝试，但**用户尚未认可v2听感**。

因此保留“合奏先验证、区分相位/节奏/和声/遮蔽”的流程。不要将v2中的100%鼓贝重合、每小节一两个和弦、零相邻半音写成所有歌曲的要求，也不要把技术测试通过写成用户认可。
